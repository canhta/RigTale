# Repository Review: The MLT / Glaxnimate / Lottie Chain

**Screened under:** `SPIKE-C001` (`RGT-S001`), read-only static source inspection with full commit history.

Three repositories screened together because a documentation-level finding proposed them as a complete open production chain: an agent emits Lottie JSON as data, a published JSON Schema validates it without execution, Glaxnimate or a rasteriser renders assets, and MLT composites tracks and renders an exact frame range headlessly.

## Chain Verdict

**The chain holds structurally at three of four joints and breaks at two specific points.**

**Holds.** MLT gives integer-frame seek and genuine range restriction, a headless file writer with frame dropping disabled by default, a full LGPL-2.1 compositing set that survives a GPL-free build, and a producer that reads Lottie and emits RGBA with alpha preserved. Lottie's schema is JSON Schema Draft 2020-12 with layer parenting, track mattes, precompositions, and time remapping.

**Break 1 — the Lottie-to-MLT joint is GPLv3 and unbuilt.** `src/modules/glaxnimate/producer_glaxnimate.yml:8` declares GPLv3. The module is gated behind a CMake option that **defaults off** (`CMakeLists.txt:27`), requires Qt6 Widgets plus Glaxnimate's core built from a git submodule that is **empty in this clone**, and constructs a full GUI application object (`producer_glaxnimate.cpp:188`). The "MLT reads Lottie natively" link is the most expensive and least verified in the chain.

**Break 2 — Lottie cannot express a bone rig.** Decisive, and covered below.

**Break 3, softer — validating without executing needs a build step.** The schema uses internal references across 81 files; the single merged schema that the project's own test harness consumes is **not committed**, and is generated by a script from an external package.

## MLT: Frame-Exact Range Rendering

`mlt_position` is `int32_t` unless a double-position macro is defined, and that macro appears nowhere else in the tree (`src/framework/mlt_types.h:249-257`). **Positions are integer frames.**

`mlt_producer_seek` (`mlt_producer.c:337`) sets position, clamps to the playtime, and on reaching the end sets speed to zero. `melt` reads in and out from the **consumer's** properties and applies them to the top-level producer (`melt.c:1092-1099`).

**This genuinely restricts the render, not just playback**: the producer stops at the out point by setting speed to zero, and the encoder terminates when the terminate-on-pause property is set and speed reaches zero (`consumer_avformat.c:2751`, with that property defaulting to 1 at `:352`).

Isolated-shot rerender is a real primitive here. But it is driven through a **property on the consumer, not a documented CLI flag**, which is worth pinning in an executable spike.

## MLT: The Decisive Licence Finding

`CMakeLists.txt:189-198` shows that disabling GPL forces off exactly eight modules: normalize, OpenFX, plus-GPL, Qt6, resample, rubberband, vidstab, and xine.

**Everything RigTale needs for 2D cutout compositing survives, and each declares LGPL-2.1 in its service metadata:**

- **Core**: composite, luma-wipe, and **matte** transitions (replacing track A's alpha with track B's luma), mix, the mask-start and mask-apply filter pair, crop, resize, rescale, luma, brightness, time remap, colour producer, and the loader.
- **Plus — and this module is *not* GPL-gated**: `transition_affine` and `filter_affine` provide the full affine transform with keyframable rect, three-axis rotation and shear, scale, alignment, and alpha handling. Also shape-alpha, luma-key, chroma-hold, invert, and text.
- **avformat, xml, gdk** (pixbuf and pango image and text producers), and kdenlive — all LGPL-2.1.

**What is lost is the whole Qt module, and this is the sharpest nuance in the repository.** Fifteen of eighteen Qt services declare LGPL-2.1, including the blend transition with Porter-Duff modes and a keyframable rect, drop shadow, and the Qt image producer. **The entire module is disabled because three services in it are GPL.** Losing the Qt image producer matters: the extension dispatch table routes PNG to the Qt producer with pixbuf as fallback, so PNG, JPEG, and SVG loading survives — but AVIF, EXR, PSD, KRA, JXL, and HEIC become unloadable.

**Verdict: an LGPL-2.1-only MLT is a viable compositor for RigTale. It is not the configuration MLT ships or tests by default.**

## MLT: Headless and Determinism

The core library links only threads, dynamic loading, and the maths library — **no Qt, no SDL, no X11**. The `melt` front end links SDL only conditionally. A null consumer exists. Headless is real for the core chain; only the Qt and Glaxnimate modules pull a display dependency.

Determinism is controlled by one property. `real_time` defaults to `-1` for both the file-writing and null consumers, with the source comment noting separate producer and consumer threads "with no frame dropping". Frame dropping is bypassed entirely when the value is non-positive (`mlt_consumer.c:941-972`, `:1064`).

**But the absolute value also sets the worker thread count** (`:1211`, `:1437`), so a value of `-4` means four threads with no dropping — and thread count could still affect slice-parallel filters.

**No golden-image or hash test exists.** There are 792 assertions across 50 test directories, none comparing rendered pixels or checksums. `BUILD_TESTING` defaults **off**.

## MLT: The XML Validation Gap, and What Closes It

The DTD exists but **the parser never uses it**: `producer_xml.c:2070-2101` installs a bare SAX handler and checks only well-formedness. Non-validating, confirmed. Property elements are fully free-form — the DTD declares the property element as accepting anything.

**RigTale could not statically validate a production from the DTD alone.**

However, MLT ships machine-readable per-service metadata that closes most of the gap: every service has a YAML file with a schema version and **typed parameters carrying identifier, type, minimum, maximum, default, mutability, and animation support**, validated against a Kwalify metaschema (`src/framework/metaschema.yaml`) by a CMake test.

So there **is** per-service schema versioning alongside the document-level version. **RigTale should generate its validator from the service query output, not from the DTD.**

## MLT: Compositing Primitives

Present and LGPL: alpha mattes, luma-wipe and general compositing with geometry, alignment, softness, and distortion; filter-scoped masking via the start/apply pair; alpha shaping. Affine transform with keyframable rect, three-axis rotation, and shear. Z-order is track index in a tractor, with transitions bound to explicit A and B tracks and a per-track hide attribute. Keyframing offers 36 interpolation types including Catmull-Rom variants and easing curves.

**No camera and no parallax concept exists** — a search returns nothing. RigTale computes camera moves itself and emits them as per-track affine keyframes.

## MLT: Maintenance and macOS

6,740 commits, 145 authors. The lead maintainer accounts for about **64%**; the top four for about 82%. Last 12 months: 303 commits, 15 authors, with the lead at 57%. Last commit 2026-07-31. One company's copyright appears in 206 of 242 core source files.

**Bus factor 1, one vendor dominant — but unmistakably alive.**

macOS has conditional handling including a relocatable app-bundle layout defaulting on. **But the macOS CI workflow does not build** — it downloads a prebuilt tarball. **There is no in-repo macOS build or Apple Silicon evidence.**

## Glaxnimate

Lottie import **and export** both exist (`src/core/glaxnimate/io/lottie/lottie_format.cpp:12,49`). The native format is separate. A validation visitor exists but enforces only sticker-platform constraints, not Lottie conformance.

**CLI flags are real** (`src/gui/cli.cpp:60-107`): export, export format, render, render format, and frame, where frame accepts "all" and iterates writing zero-padded images.

**Headless is partial, and the details matter.** `main.cpp:55` constructs a GUI application subclass **unconditionally, before any argument parsing**. The no-GUI predicate (`cli.cpp:452-461`) returns true for render and the format-list flags — **but not for export**, so exporting still shows a splash screen and spins an event loop. Even render needs the application object and therefore an offscreen platform plugin or a display.

**The Python module is the better headless path.** It is a real pybind11 module, CI-built into a wheel, with a headless environment manager and a per-frame render call that fills a transparent ARGB image and paints via a CPU renderer — **alpha preserved, no GPU**.

**No rigs.** Glaxnimate models shapes, paths, groups, modifiers, styles, masks, compositions, and keyframed properties. There is no bone, skeleton, IK, or vertex-weight concept. The only bone tokens are Rive import cases explicitly left unimplemented.

**GPL-3.0-or-later throughout**, REUSE-compliant with per-file SPDX identifiers. **Viral for any linked RigTale component**, including the Python module. Subprocess use is the safer boundary.

Maintenance: 3,506 commits, 28 authors, one author at about **77%**. In the last 12 months, 548 commits of which the lead author has 320 and translation automation has 190 — meaning roughly **seven real human commits from anyone else in twelve months**. Bus factor 1, harder than MLT's. Now hosted under KDE, which is governance upside. macOS CI builds a disk image but the Python wheel step is **disabled**, and paths imply Intel runners.

## Lottie Spec: Cannot Express a Bone Rig

This is the decisive finding for the chain.

**What it has:** layer parenting referencing another layer by index — **transform inheritance only**; a per-layer transform with anchor, position, rotation, scale, opacity, skew, and skew axis; track mattes with five modes including inverted alpha and luma; bezier masks; precomposition assets referenced by id with time stretch, start time, and time remapping; blend modes; and **slots**, named property substitutions injected by id.

**What it lacks:** any bone, joint, skin, vertex-weight, IK, or deformer concept. **Zero occurrences in the schema.** Rotation is a scalar per layer, and there is no mechanism by which moving one node deforms another node's path data.

**Implication for RigTale's fixed-cast premise: precompositions plus slots are the closest analogue to a reusable character** — a precomp asset is the puppet, instanced per shot, with slots swapping values. But the rig itself — bone hierarchy, pose solving, deformation — must live in RigTale's own upstream representation and be **baked down** to Lottie transform keyframes per shot.

The chain carries the fixed cast as **reusable precompositions, not as rigs.**

## Lottie Spec: Schema Completeness

Draft 2020-12, version pinned, 81 files organised as namespaces covering compositions, layers, assets, shapes, properties, values, constants, and helpers.

**The subset self-declaration** is explicit in the documentation: the specification "is still a work in progress, this document contains a subset of features that have been approved". Missing versus real-world Lottie: **text layers, cameras, effects, expressions, and audio**.

**Worse for a validator, the schema is permissive by design.** Unknown layer and unknown shape definitions deliberately admit anything whose type is not in the known enumeration, and the documentation states implementations may store additional data. **It will pass documents it does not model.** Required fields are thin.

**RigTale would need its own stricter profile on top.**

Licence and governance are the cleanest of the three: Community Specification License 1.0 for the specification with MIT for code, a real governance policy with maintainer, editor, and participant roles, consensus approval, and written appeals. **No copyleft on RigTale.**

Health: 116 commits, 17 authors, no single dominant contributor, but only **13 commits in the last 12 months**. Slowing, yet multi-vendor — genuinely better bus factor than either code repository.

## Patterns to Adopt or Adapt

1. **Machine-readable service metadata as the validation source of truth** — typed parameters with bounds, defaults, mutability, and animation support, validated against a metaschema and queryable at runtime. This is precisely "AI writes data, validator checks it without executing".
2. **An explicit determinism switch** that disables all frame dropping and time-based adaptivity. RigTale should make its equivalent non-optional and assert it.
3. **Terminate-on-pause plus producer in and out as the range-render contract** — the shot boundary is data, not a CLI convention.
4. **Normaliser chains as ordered, fallback-listed configuration** — declarative preference lists with graceful degradation.
5. **Extension-to-producer dispatch as a data table.**
6. **REUSE and per-file SPDX licensing** — mandatory for a redistributable open project.
7. **Lottie precompositions plus slots** as the reusable-asset pattern for a fixed cast.
8. **An unknown-type forward-compatibility escape hatch — but only paired with a strict internal profile.**

## Patterns to Avoid

1. **A DTD that nothing validates against** — documentation cosplaying as a schema.
2. **Free-form name-value properties** with no per-property type binding in the document format.
3. **Module-level licence gating that discards compatible services.** Fifteen LGPL services are lost because three GPL services share a directory. Partition by licence, not by convenience.
4. **Constructing a GUI application object before parsing arguments**, and omitting a subcommand from the no-GUI list. Headless must be the default path, not an escape.
5. **Testing disabled by default.**
6. **Zero golden-image or hash tests in pixel-producing code** — true of both MLT and Glaxnimate.
7. **CI that downloads a prebuilt binary instead of building**, and a disabled packaging step.
8. **A schema whose usable merged form is not committed.**

## Conclusions

**MLT — `adapt`, leaning `adopt` for the compositor role.** It is the only component delivering integer-frame range rendering, headless file output, multi-track z-ordered compositing with alpha mattes and affine transforms, **and** surviving an LGPL-2.1-only build with those capabilities intact. Its typed service metadata directly serves RigTale's static-validation requirement. `adapt` rather than `adopt` because RigTale must build in an untested configuration, generate its own strict schema from the service query rather than trusting MLT XML, and supply camera and parallax itself.

**Glaxnimate — `reference`, defer.** It is the only open Lottie writer here and its render call is a clean CPU rasteriser, but GPLv3 makes linked use viral, its headless story requires a platform plugin on every path, export still shows a splash screen, bus factor is effectively one, and it has no rig capability. Reference its exporter and its licensing discipline; treat any runtime use as a subprocess boundary.

**Lottie spec — `adopt` as the validation contract, with a RigTale profile.** Cleanest licence, real multi-vendor governance, and a schema a validator can run without executing anything. But it is an explicit subset, deliberately permissive, missing text, cameras, and effects, and **cannot express a bone rig**. Adopt it as the **shot-level baked interchange format underneath a RigTale-owned rig representation**, and define a strict profile that closes the unknown-type holes.
